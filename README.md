# android-smooth-markdown

Native Kotlin/Jetpack Compose library and demo, based on [Flutter Smooth Markdown](https://github.com/JackCaow/flutter-smooth-markdown) version 0.10.0.

## Status

Reader and editor work in progress. The library renders headings, paragraphs, inline emphasis, links, enhanced code blocks with language labels, copy and initial syntax colors, blockquotes, ordered/bullet/task lists, GFM tables, standalone or mixed inline network/bundled-asset bitmap and SVG images, footnotes, collapsible `details` blocks, inline `$...$` and display `$$...$$` math, and horizontal rules. Opt-in parser/renderer plugins provide mentions, hashtags, emoji shortcodes, admonitions, AI thinking/artifact/tool-call blocks, and an initial Mermaid flowchart/sequence/pie/timeline/Gantt/Kanban/Radar/XYChart/ER renderer. Inline images without explicit dimensions use a 32 dp placeholder. It supports per-text-block selection, `Flow<String>` chunk accumulation with a 50 ms update throttle and completion flush, and blocks unsafe link/image schemes. Opt-in HTML handles common inline formatting, safe link styling, bounded font/color styles, `br`, `hr`, standalone or mixed `img` with pixel dimensions and alt fallback, and `div`/`p`/`center`/`blockquote` containers; streaming withholds incomplete tags outside code. The source editor supports UTF-16 selections, undo/redo, grouped transactions, search, formatting commands, and source/preview/split layouts. Source-backed GFM tables support insertion, cell replacement, row/column edits, alignment, and deletion at the current selection. Formatted mode edits paragraphs, ATX headings, fenced code, ordered/bullet/task items including nested items and continuation lines, and GFM table cells with add/remove row and column controls. Untouched list source is preserved; Enter splits supported list items and Tab/Shift+Tab changes their nesting with undo/redo. Empty top-level list exit, bounded top-level outdent, block/list/table range selection, and source-backed formatting for supported inline marks are implemented. Richer list and table cell editing, unsupported inline constructs, full Mermaid syntax, intrinsic image sizing, full HTML behavior, character-level drag selection across blocks, richer AI chat presentation, and complete Flutter style-sheet coverage still need implementation. Do not treat this as a parity release.

Open this folder in Android Studio or run `./gradlew :app:assembleDebug`. Run `./gradlew :smoothmarkdown:testDebugUnitTest` for parser and URL-policy tests.

The Editor demo offers Flutter's 18 default slash commands and search aliases, source-backed Find navigation, and Focus mode; Ctrl+F opens and focuses Find, while Ctrl+Shift+Enter toggles Focus. Focus hides the editor toolbar but keeps the Demo introduction and any open Find bar. Host-configured slash commands and toolbar command filtering are available; keyboard menu navigation and formatted-view search highlighting remain open. The drawer translates its Flutter labels in six languages and persists the selection. Math, Streaming, Footnotes, HTML Tags, and Plugin System use Flutter example fixtures. HTML Tags has the original HTML switch and 40 ms stream using native `StreamMarkdown`; toggling HTML keeps the current stream and reprojects unfinished tags. Chat List streams one of Flutter's four mock replies after a 500 ms delay and shows live parse-cache entries, capacity, utilization, and Clear Cache. Both chat demos render active assistant bubbles with `StreamMarkdown` from a per-message cumulative source, throttled at 50 ms; completed bubbles switch to stable `SmoothMarkdown` content. Lazy list recycling resumes from the latest complete prefix. AI Chat retains six Flutter quick prompts and mock streaming; Settings accept separate runtime API keys and models for DashScope Qwen or DeepSeek SSE streaming, with a thinking option and real-API switch. Keys stay in memory and are never bundled or persisted. A real request needs a valid key for the selected provider and network access. Conversation List loads Flutter's 12 conversations and 29 messages, showing unread badges, relative times, a detail page, copy-all, per-message Copy, native rendered-text selection in the bubble, and light/dark mode. The source-backed editor patches a single table cell in place, preserving unrelated spacing, alignment markers, and line endings during that edit. The public components include `SmoothMarkdown(markdown, modifier, onLinkClick, onImageClick, enableHtml, styleSheet)`, `StreamMarkdown(chunks, ..., enableHtml, styleSheet)`, `MarkdownEditorController`, and `SmoothMarkdownEditor(controller, modifier, onSave)`. For image metadata, both reader APIs also accept `onImageClickWithMetadata = { source, alt, title -> ... }`; if both image callbacks are supplied, both run. This applies to standalone, inline, and enabled HTML images. HTML is disabled by default. CommonMark Java parses Markdown to an AST; Compose renders each block directly. The [Flutter source and tests](https://github.com/JackCaow/flutter-smooth-markdown) remain the behavior reference.

Reader parsing uses a shared LRU by default; `enableCache = false` bypasses it for changing content. Set `selectable = true` to select rendered text across the visible Markdown blocks. An optional `SmoothSelectionController` exposes `selectAll()`, `select(range)`, `clear()`, and `selectedText` while the reader is mounted. Library-owned selection gives horizontal rules, standalone images, and display math invisible word-selectable geometry so a long press can begin on those blocks. The invisible text carries a private Compose annotation. For a selection containing an anchor, the Reader replaces Compose's Copy menu callback with one that writes only unannotated selected text, including when just one anchor character is selected; it preserves the menu item's label and icon. Android's system floating Copy can write directly through `LocalClipboard`, so the Reader also filters a plain-text clipboard write only when its payload exactly matches the current annotated selection. The legacy Android text toolbar callback and Ctrl/Cmd+C use the same filter. Without an anchor, the normal Copy callback runs, and unrelated clipboard payloads are forwarded unchanged. Anchored selections are copied as plain text. Flutter's `contextMenuBuilder`, table-wide non-text geometry, and selection when a host owns the outer `SelectionContainer` remain open.

The Reader controller also exposes `selectWordAt(windowPosition)` and `selectParagraphAt(windowPosition)`, using coordinates in the Android window; a point outside rendered text clears the current selection. These calls synchronously select all registered Compose text to calculate the range, then narrow it to the requested word or paragraph. Supply `selectionMenuActions = listOf(SmoothSelectionMenuAction("copy-visible", "Copy visible") { selectedText -> ... })` to add actions to Compose's native selection menu. Each action receives the visible selection after the Reader's annotation-based anchor filter and performs only the host callback; a custom Copy action must write to the clipboard itself. Set `showDefaultCopyAction = false` to hide the native Copy item when supplying a replacement. `StreamMarkdown` forwards these options. This extends the native menu but does not implement Flutter's fully custom `contextMenuBuilder`. The controller's existing `selectedText` remains the raw Compose selection, which can include invisible non-text anchors; menu callbacks and plain-text Copy apply the filter. Four focused Android API 35 emulator tests cover word/paragraph selection, updated Markdown, native menu composition/callback, and anchor filtering. The menu test uses a recording Compose toolbar provider; the separate manual floating-menu probe below validates actual system Copy, but a custom action writing to the system clipboard remains unverified.

Android API 35 emulator acceptance on 2026-09-29: 10 earlier focused instrumentation tests passed across Reader selection, list editing, and Conversation Demo navigation/selection. One existing formatted-heading drag test failed: the drag selected only the first heading. Focused JVM tests and AndroidTest compilation passed for the annotation-based Copy change. Emulator tests verified rule/image long presses and image taps, the Compose toolbar provider's Copy callback across both blocks, one-character anchor fragments selected from the middle, a custom menu action, and Ctrl+C. A later Pixel 7 API 35 read-only AVD session exposed a system floating Copy leak: tapping Copy on a range spanning a rule anchor and one visible character placed the hidden anchor on the clipboard. After routing the platform clipboard write through the annotation filter, the same actual floating-menu tap copied exactly that visible character; the manual probe passed 1/1, and focused Reader instrumentation passed 5/5. [Screenshot and command evidence](benchmarks/evidence/android-reader-system-copy-one-char.txt) are included. Physical-device behavior remains unverified.

`StreamMarkdown` accepts the same text-selection and code-block builder/options controls as the reader, plus `loadingContent` before its first value and `errorContent` when collection fails. It reparses the changing prefix without filling the shared parse cache. Both the chunk `Flow` and cumulative `StateFlow` overloads expose these controls.

The editor optionally accepts suspend host callbacks `onPickImage`, `onImportMarkdown`, `onExportMarkdown`, and `onExportPdf(markdown, html)`, plus `onImagePickEvent` and `onHostActionError`. Supply them to show Image, Import, Export, and Export PDF toolbar actions. The host owns Android picker, upload, and storage UI; `onPickImage` returns `MarkdownEditorImageSelection(url, alt, title)` and `onImportMarkdown` returns Markdown text. A null or blank result, callback failure, or a document changed while a picker was open leaves the source untouched. Successful image and import insertion each create one undo step. Export receives the exact source snapshot and never edits it. The demo uses bundled sample callbacks; replace them with your app's picker and storage implementation.

The editor accepts `capabilities = MarkdownEditorCapabilities(disabledCommands = setOf(MarkdownEditorCommand.TABLE))` to hide built-in commands from its toolbar and slash menu and disable their keyboard shortcuts. Pass `toolbarCommands = listOf(MarkdownEditorCommand.BOLD, MarkdownEditorCommand.BLOCKQUOTE)` to choose and order built-in toolbar buttons. Pass `customSlashCommands = listOf(MarkdownEditorSlashCommand(title = "Callout", searchText = "note", markdown = "> Note"))` to append a host action to the slash menu. A command can instead provide `onSelected = { query -> "> $query" }`; the editor checks that the trigger is still current after the suspend callback and inserts the returned Markdown in one undo step. `enableSlashCommands = false` hides the slash menu. Hardware Ctrl+B/I/K apply Bold, Italic, and Link to the current source or formatted selection; Ctrl+Z/Y handle history. Hosts can set `enableKeyboardShortcuts = false`, intercept key-down events with `onShortcut`, and observe accepted built-in commands with `onCommand`. Host calls to `MarkdownEditorController.applyCommand` remain independent of these UI settings.

Formatted range commands accept UTF-16 offsets in visible paragraph/ATX-heading text. `MarkdownFormattedTextSelection(source = controller.text, anchor = MarkdownFormattedTextPosition("block-0", 2), focus = MarkdownFormattedTextPosition("block-1", 4))` can be passed to `controller.applyInlineCommandToFormattedTextSelection(selection, MarkdownEditorCommand.BOLD)`. The command edits each selected paragraph/heading as one undo step, preserves unselected blocks and link destinations, and validates the result against CommonMark before committing. Partial ranges inside existing bold, italic, and links are supported when a source-safe Markdown representation exists. Stale source snapshots, intervening non-text blocks, nested links, code/wikilink intersections, unsafe or Markdown-ambiguous link destinations, split UTF-16 surrogate pairs, and syntax that cannot retain the original visible text and marks are rejected without changing history. The current formatted drag UI selects whole blocks; character-level cross-block drag handles have not been added.

Formatted mode also accepts `customBlockMatcher`, `customBlockBuilder`, and `customBlockEditorBuilder`. The matcher must explicitly identify blocks owned by the host; without it, every block keeps its default view. For example, match `block.kind == MarkdownBlockKind.RAW && block.source.startsWith("<my-card>")`, render a Compose card, and call the supplied `edit`, `replaceMarkdown`, `delete`, or `finishEditing` actions. Replacement and deletion return `false` if the document changed since the view was built or if reparsing would alter neighboring blocks. A successful action is one source-backed undo step, including when replacement changes the block syntax.

For a host-owned `:::custom` block, register `DelimitedBlockPlugin("custom")` and pass the registry to `MarkdownEditorController(markdown, parserPlugins = plugins)`. The editor then uses the same registry for its source-backed blocks and Reader preview. Match `block.kind == MarkdownBlockKind.RAW && block.source.startsWith(":::custom")` to show a host Compose view and editor. The block's exact Markdown, including line endings, remains available in the callback. Subclass `DelimitedBlockPlugin` to customize its Reader rendering. More complex syntax can implement `BlockParserPlugin` for Reader parsing and `SourceBlockParserPlugin` for whole-document editor spans; `SourceBlockParseResult.linesConsumed` must stay within the remaining input and cover complete top-level CommonMark blocks. Invalid or null results fall back to CommonMark.


`MarkdownStyleSheet` supports MaterialTheme-backed defaults plus `light()`, `dark()`, `github(dark)`, and `vscode(dark)` presets. Use `copy` to override colors, text styles, or spacing:

```kotlin
SmoothMarkdown(
    markdown = content,
    styleSheet = MarkdownStyleSheet.github(dark = true).copy(
        linkColor = Color.Cyan,
        blockSpacing = 16.dp,
    ),
)
```

The demo's Theme button cycles through all presets. This first native style API covers common reader elements; Flutter's full stylesheet includes additional properties such as alternating table rows and separate inline-format styles.

Code blocks accept `codeBlockDecoration = MarkdownCodeBlockDecoration(backgroundColor, borderColor, borderWidth, cornerRadius)` and `codeBlockPadding = PaddingValues(...)`. These match Flutter's actively rendered code block decoration and per-edge padding. Existing `codeBackground` and uniform `codePadding` remain supported; a decoration fill takes precedence over `codeBackground`.

Math uses the native [RaTeX Android renderer](https://github.com/erweixin/RaTeX) for formulas including fractions, roots, and scripts. Unsupported TeX shows its source text. `CodeBlockOptions` controls copying, language labels, and preliminary highlighting for Kotlin, Swift, Dart, Java, JavaScript/TypeScript, Python, JSON, Bash, and SQL. The public `codeBlockBuilder` and `onCodeCopied` parameters allow custom code rendering and copy handling.

## Parser and renderer plugins

Plugins are disabled by default. Create a registry before composing the reader and pass it to `SmoothMarkdown`:

```kotlin
val plugins = remember {
    ParserPluginRegistry().also {
        it.registerAll(listOf(MentionPlugin(), HashtagPlugin(), EmojiPlugin(), AdmonitionPlugin(), MermaidPlugin(), ThinkingPlugin(), ArtifactPlugin(), ToolCallPlugin()))
    }
}
SmoothMarkdown(markdown = content, plugins = plugins)
```

`InlineParserPlugin` provides a one-character trigger, `canParse`, `parse`, and `render` hooks. `BlockParserPlugin` provides `canStart`, `createNode`, `isClosingLine`, `complete`, and a Compose `RenderBlock` hook; the node-aware `isClosingLine(node, line)` variant supports multiple delimiter styles. Its `parseFencedCodeBlock` hook converts CommonMark fenced blocks while preserving ordinary code on a `null` result. Custom nodes extend `PluginInlineNode` or `PluginBlockNode`. A `null` parse result lets the next plugin or CommonMark handle the source. Higher priorities run first; equal priorities keep registration order. Registry IDs must be unique within the block or inline group. `copy`, `clear`, lookup, and unregister operations are available. Configure the registry before passing it to Compose; provide a new registry instance after changing its contents so the Markdown AST is rebuilt.

The built-in plugins match Flutter's mention, hashtag, emoji, admonition, and Mermaid fence syntax. Emoji supports a custom shortcode map. Admonition content is parsed as Markdown. The opt-in Thinking, Artifact, and ToolCall plugins parse Flutter's corresponding AI chat block syntaxes. Thinking starts collapsed and can be expanded; artifact and tool inputs are rendered as selectable text without executing HTML or tool calls. Code artifacts reuse the native code block renderer. These readers do not yet provide artifact download, live tool status updates, or rich HTML/component previews.

## Mermaid prototype

`MermaidDiagramView(source)` is a standalone Compose view backed by `MermaidParser` and `MermaidLayout`. Register `MermaidPlugin()` to render supported fenced `mermaid` blocks in `SmoothMarkdown` or `StreamMarkdown`; without it, fences remain ordinary code. Empty or unsupported diagram families also remain code. Both backtick and tilde fences are recognized; the parsed node retains fence type, info, and optional `theme=` metadata. The renderer currently uses the Compose color scheme rather than the fence's `theme=` setting. Supported flowchart syntax: `graph`/`flowchart` with `TD`/`TB`/`BT`/`LR`/`RL`; plain nodes and rectangle, rounded, stadium, diamond, hexagon, circle, subroutine, cylinder, asymmetric, parallelogram, and trapezoid node declarations; chained solid/thick/dotted edges with `|label|`; `classDef`, `class`, inline `style`, and nested `subgraph` membership. Supported sequence syntax: `sequenceDiagram`, `participant`/`actor` with aliases, and `->`, `-->`, `->>`, `-->>`, `-x`, `--x`, `-)`, `--)` messages with optional labels. Pie supports title, `showData`, quoted or unquoted labels, positive decimal slices, percentages, and a legend. Timeline supports title, period/event rows, multiple events per period, and descriptions. Gantt supports titles, sections, explicit dates, day/week/month/year durations, task status, dependencies, milestones, and a scrolling date grid. Kanban supports columns, task metadata, priority colors, WIP badges, and `ticketBaseUrl` frontmatter parsing. Radar supports labeled axes and curves, scale options, polygon/circle graticules, and a legend. XYChart supports category labels, numeric y range, grouped bars, line series, negative values, and horizontal orientation. ER diagrams support entity aliases, attribute compartments, labeled solid or dotted relations, and all four cardinalities at both endpoints. Flowcharts now preserve nested `subgraph` containers, group edges, and accessibility group labels; Flutter issue46 and group-boundary fixtures are covered by unit tests. The Canvas renderer draws these diagram types natively with scrolling for larger content.

For a quick local preview after installing the Demo APK, run `adb shell am start -n com.jackcaow.smoothmarkdown.demo/.MermaidDemoActivity` and use the button to cycle through flowchart, sequence, pie, timeline, Gantt, Kanban, Radar, XYChart, and ER. Gantt `todayMarker` draws the current-day line when it falls within the chart range; `excludes` and `axisFormat` are parsed but do not change the chart, matching the current Flutter painter.  Kanban ticket URLs are retained but not opened. XYChart numeric x-axis ranges are retained but still use series indices for point positions. ER layout uses a simple non-overlapping row or column and does not yet provide full Dagre routing for dense graphs. Other Mermaid diagram families, advanced flowchart routing and shapes, non-state self loops, composite state blocks, sequence notes/activation/control blocks, responsive layout, and full Flutter visual parity remain open.
