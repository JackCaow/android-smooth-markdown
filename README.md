# android-smooth-markdown

Native Kotlin/Jetpack Compose library and demo, based on [Flutter Smooth Markdown](https://github.com/JackCaow/flutter-smooth-markdown) version 0.10.0.

## Use in a Compose app

The library is currently available as source code; **there is no published Maven artifact or dependency coordinate yet**. Place this repository under your app project, for example at `third_party/android-smooth-markdown`, then add its library module to your app's `settings.gradle.kts`:

```kotlin
include(":smoothmarkdown")
project(":smoothmarkdown").projectDir = file("third_party/android-smooth-markdown/smoothmarkdown")
```

Add the module dependency to your app module's `build.gradle.kts`:

```kotlin
dependencies {
    implementation(project(":smoothmarkdown"))
}
```

Render Markdown from a composable:

```kotlin
import androidx.compose.foundation.layout.fillMaxSize
import androidx.compose.runtime.Composable
import androidx.compose.ui.Modifier
import com.jackcaow.smoothmarkdown.SmoothMarkdown

@Composable
fun MarkdownScreen(content: String) {
    SmoothMarkdown(
        markdown = content,
        modifier = Modifier.fillMaxSize(),
        useEnhancedComponents = true,
    )
}
```

Your app must enable Jetpack Compose and resolve the Android/Kotlin plugins and repositories required by this module. This repository's [Gradle files](build.gradle.kts) show a working toolchain; the included `app` module is a runnable example. The library requires Android API 24 or newer.

## Status

Reader and editor work in progress. The library renders headings, paragraphs, inline emphasis, links, enhanced code blocks with language labels, copy and initial syntax colors, blockquotes, ordered/bullet/task lists, GFM tables, standalone or mixed inline network/bundled-asset bitmap and SVG images, footnotes, collapsible `details` blocks, inline `$...$` and display `$$...$$` math, and horizontal rules. Opt-in parser/renderer plugins provide mentions, hashtags, emoji shortcodes, admonitions, AI thinking/artifact/tool-call blocks, and an initial Mermaid flowchart/sequence/pie/timeline/Gantt/Kanban/Radar/XYChart/ER renderer. Inline and block images use their decoded intrinsic size once loaded, preserve aspect ratio for one-sided HTML dimensions, and fit within the available Markdown width. Inline images use a 32 dp placeholder while loading. It supports selection across mounted prose, tables, images, rules, built-in code blocks, and expanded `details` blocks, `Flow<String>` chunk accumulation with a 50 ms update throttle and completion flush, and blocks unsafe link/image schemes. Opt-in HTML handles common inline formatting, safe link styling, bounded font/color styles, `br`, `hr`, standalone or mixed `img` with pixel dimensions and alt fallback, and `div`/`p`/`center`/`blockquote` containers; streaming withholds incomplete tags outside code. The source editor supports UTF-16 selections, undo/redo, grouped transactions, search, formatting commands, and source/preview/split layouts. Source-backed GFM tables support insertion, cell replacement, row/column edits, alignment, and deletion at the current selection. Formatted mode edits paragraphs, ATX headings, fenced code, ordered/bullet/task items including nested items and continuation lines, explicit blockquote lines, and GFM table cells with add/remove row and column controls. Untouched list and quote source is preserved; Enter splits supported list items and Tab/Shift+Tab changes their nesting with undo/redo. Empty top-level list exit, bounded top-level outdent, block/list/table range selection, and source-backed formatting for supported inline marks are implemented. Quote line endpoints support Markdown copy and same-quote-line or same-depth multiline edit; lazy continuation quote lines still use raw source fallback. Formatted block selection can turn contiguous top-level paragraphs and ATX headings into one bullet, ordered, or task list or one quote, or convert each block to a paragraph or H1–H6. These source-backed changes reparse before committing and use one undo step; unsupported blocks, setext headings, and transforms that merge with untouched neighbors are rejected. Richer list and table cell editing, unsupported inline constructs, full Mermaid syntax, full HTML behavior, drag selection through offscreen virtualized blocks, richer AI chat presentation, and complete Flutter style-sheet coverage still need implementation. Do not treat this as a parity release.

The public components include `SmoothMarkdown(markdown, modifier, onLinkClick, onImageClick, enableHtml, styleSheet)`, `StreamMarkdown(chunks, ..., enableHtml, styleSheet)`, `MarkdownEditorController`, and `SmoothMarkdownEditor(controller, modifier, onSave)`. For image metadata, both reader APIs also accept `onImageClickWithMetadata = { source, alt, title -> ... }`; if both image callbacks are supplied, both run. This applies to standalone, inline, and enabled HTML images. HTML is disabled by default. CommonMark Java parses Markdown to an AST; Compose renders each block directly. The [Flutter source and tests](https://github.com/JackCaow/flutter-smooth-markdown) remain the behavior reference.

`SmoothMarkdown` and both `StreamMarkdown` overloads accept `useEnhancedComponents`, defaulting to `false` as in Flutter. The standard mode keeps plain headings and quotes and shows code without copy/language controls or syntax colors. Enhanced mode adds the H1/H2 accent, gradient quote with icon, and code controls/highlighting; the Flutter Demo uses it for reader samples, streams, assistant bubbles, and conversation messages. Native links retain their underline and tap behavior in both modes; Flutter's hover animation and external-link icon are not yet represented in Compose. A custom `codeBlockBuilder` still takes precedence in either mode.
`SmoothMarkdownEditor` forwards the same choice into Preview and Split and defaults it to `true`, matching Flutter's editor default.

The editor accepts `editorTheme = MarkdownEditorTheme(...)` for its container, toolbar, search and suggestion panels, source and preview panes, formatted blocks, selections, and table cells. Null fields use Material defaults. To share editor styling, wrap multiple editors in `CompositionLocalProvider(LocalMarkdownEditorTheme provides sharedTheme) { ... }`; a per-editor theme overrides only the fields it supplies. For example, `MarkdownEditorTheme(sourcePadding = 20.dp, tableBorderColor = Color.Gray, suggestionPanelColor = Color.White)` changes those surfaces without changing the Markdown reader's `MarkdownStyleSheet`.

Reader parsing uses a shared LRU by default; `enableCache = false` bypasses it for changing content. Set `selectable = true` to select rendered text across visible Markdown blocks, including built-in fenced and indented code; language labels and Copy buttons stay outside the selected content. Custom code builders retain their own block boundary. An expanded `details` block shares a selection group with its nearest prose neighbors; its collapsed body and disclosure arrow stay out of selected text. Offscreen `LazyColumn` items remain outside Compose’s registered selection. An optional `SmoothSelectionController` exposes `selectAll()`, `select(range)`, `clear()`, and `selectedText` for the mounted Compose region. For an explicit whole-document copy, use `copyAllDocumentText()` or read nullable `documentText`; these project parsed blocks without mounting offscreen views and exclude collapsed details and non-text images/rules. The copy method returns false if the reader is not mounted, the document has no text, or a custom block renderer cannot provide a reliable text projection. Custom block builders and block parser plugins can implement `documentText(node)` to make their rendered text available to this path. Document copy does not create selection handles or make the native Select All menu document-wide. The projection preserves deterministic block paths and UTF-16 offsets internally for later cross-block selection work. Library-owned selection gives horizontal rules, standalone images, and display math invisible word-selectable geometry so a long press can begin on those blocks. The invisible text carries a private Compose annotation. For a selection containing an anchor, the Reader replaces Compose's Copy menu callback with one that writes only unannotated selected text, including when just one anchor character is selected; it preserves the menu item's label and icon. Android's system floating Copy can write directly through `LocalClipboard`, so the Reader also filters a plain-text clipboard write only when its payload exactly matches the current annotated selection. The legacy Android text toolbar callback and Ctrl/Cmd+C use the same filter. Without an anchor, the normal Copy callback runs, and unrelated clipboard payloads are forwarded unchanged. Anchored selections are copied as plain text. Flutter's `contextMenuBuilder`, table-wide non-text geometry, and selection when a host owns the outer `SelectionContainer` remain open.

For native whole-document selection, call `selectAllDocument()` on a mounted, selectable Reader. The request returns `true` when accepted; the Reader then temporarily mounts all parsed blocks in a scrollable Column and applies Compose Select All after layout, so the system selection and Copy path can include text that was previously offscreen. It returns `false` without changing the view for an incomplete text projection, any custom block or inline builder/plugin block, a custom code/image builder, more than 512 text blocks, more than 2,048 parsed render nodes, or more than 100,000 UTF-16 text units. Supplying copy text for a custom renderer does not prove that its view participates in the native selection. Clearing the selection restores LazyColumn. Normal reading remains virtualized; full selection uses memory proportional to the bounded document. This path has a physical-device UI test but has not yet passed on hardware. Native drag across offscreen LazyColumn items and fully custom renderer boundaries remain open.

For an unchanged `selectAllDocument()` selection, Copy and host menu actions use the built-in renderers' semantic text: exact code content, image alt text, tab-separated table cells, inline and display math source, and the body of expanded `details`. The native Compose region still supplies handles over text, code, table cells, and details text; images and display math contribute invisible selectable geometry. Moving a handle changes the native selected-text snapshot, so subsequent Copy returns to the ordinary partial-selection path and omits non-text anchor geometry. A partial range through an image or display-math block does not yet copy its alt or math source. Custom renderer boundaries remain unsupported for native whole-document selection.

The Reader controller also exposes `selectWordAt(windowPosition)` and `selectParagraphAt(windowPosition)`, using coordinates in the Android window; a point outside rendered text clears the current selection. These calls synchronously select all registered Compose text to calculate the range, then narrow it to the requested word or paragraph. Supply `selectionMenuActions = listOf(SmoothSelectionMenuAction("copy-visible", "Copy visible") { selectedText -> ... })` to add actions to Compose's native selection menu. Each action receives the visible selection after the Reader's annotation-based anchor filter and performs only the host callback; a custom Copy action must write to the clipboard itself. Set `showDefaultCopyAction = false` to hide the native Copy item when supplying a replacement. `StreamMarkdown` forwards these options. This extends the native menu but does not implement Flutter's fully custom `contextMenuBuilder`. The controller's `selectedText`, menu callbacks, and plain-text Copy all omit private non-text anchors; `selectedText` uses the same newline joining as the visible Copy action. The menu test uses a recording Compose toolbar provider; the separate manual floating-menu probe below validates actual system Copy, but a custom action writing to the system clipboard remains unverified.

`StreamMarkdown` accepts the same text-selection and code-block builder/options controls as the reader, plus `loadingContent` before its first value and `errorContent` when collection fails. It reparses the changing prefix without filling the shared parse cache. Both the chunk `Flow` and cumulative `StateFlow` overloads expose these controls.

The editor optionally accepts suspend host callbacks `onPickImage`, `onImportMarkdown`, `onExportMarkdown`, and `onExportPdf(markdown, html)`, plus `onImagePickEvent` and `onHostActionError`. Supply them to show Image, Import, Export, and Export PDF toolbar actions. The host owns Android picker, upload, and storage UI; `onPickImage` returns `MarkdownEditorImageSelection(url, alt, title)` and `onImportMarkdown` returns Markdown text. A null or blank result, callback failure, or a document changed while a picker was open leaves the source untouched. Successful image and import insertion each create one undo step. Export receives the exact source snapshot and never edits it. By default, the Demo retains the Flutter example's fixed image URL, fixed imported Markdown, export-length display, and original image rendering. Turn on **Use device files** in the editor page to use Android's document picker for images and Markdown import, and Create Document for exact UTF-8 Markdown export. In that mode, picked PNG, JPEG, GIF, and WebP images are copied into the Demo's persistent private files and inserted as `demo-images/<UUID>.<ext>`; the editor's `imageBuilder` resolves those aliases in Preview, Split, and formatted image blocks after an app restart. An exported `.md` file preserves that relative alias but does not bundle the private image bytes. Picker cancellation leaves source and selection untouched; I/O errors reach `onHostActionError`. Host apps can supply their own uploader and resolver through `onPickImage` and `imageBuilder`.

Hosts can observe committed Markdown with `onChanged`, source UTF-16 selection changes with `onSelectionChanged`, source-field focus transitions with `onFocusChanged`, and display mode requests with `onModeChanged`. Pass `mode` to let the host own Source/Preview/Split/Formatted mode; without it, the controller continues to own the mode. `initialFocusMode` and `onFocusModeChanged` expose the distraction-free toggle. IME composition stays in the controller for live editing, while `onChanged` fires after composition commits; undo, redo, and host source edits also notify. `onPerformanceSnapshot` coalesces state changes after a Compose frame and reports UTF-16 source length, semantic block count, mode, source composition, find matches, and visible slash suggestions. The formatted segment cache and formatted wikilink popup have no equivalent host-visible Android state, so their snapshot properties are null.

The editor accepts `capabilities = MarkdownEditorCapabilities(disabledCommands = setOf(MarkdownEditorCommand.TABLE))` to hide built-in commands from its toolbar and slash menu and disable their keyboard shortcuts. Pass `toolbarCommands = listOf(MarkdownEditorCommand.BOLD, MarkdownEditorCommand.BLOCKQUOTE)` to choose and order built-in toolbar buttons. Hosts can insert Compose controls before the mode buttons with `toolbarLeading = listOf({ TextButton(...) { Text("Host") } })` and after Find with `toolbarTrailing`; `toolbarBuilder = { defaultToolbar -> ... }` can wrap or replace the complete native toolbar. `showToolbar = false` hides it while keeping the source, Find results, and suggestions available. Focus mode hides the toolbar and retains its Exit focus control by default. Pass `customSlashCommands = listOf(MarkdownEditorSlashCommand(title = "Callout", searchText = "note", markdown = "> Note"))` to append a host action to the slash menu. A command can instead provide `onSelected = { query -> "> $query" }`; the editor checks that the trigger is still current after the suspend callback and inserts the returned Markdown in one undo step. `enableSlashCommands = false` hides the slash menu. Hardware Ctrl+B/I/K apply Bold, Italic, and Link to the current source or formatted selection; Ctrl+Shift+S/X applies Strikethrough, and Ctrl+Z/Y handle history. Hosts can set `enableKeyboardShortcuts = false`, intercept key-down events with `onShortcut`, and observe accepted built-in commands with `onCommand`. Host calls to `MarkdownEditorController.applyCommand` remain independent of these UI settings.

Formatted range commands accept UTF-16 offsets in visible paragraph/ATX-heading text. `MarkdownFormattedTextSelection(source = controller.text, anchor = MarkdownFormattedTextPosition("block-0", 2), focus = MarkdownFormattedTextPosition("block-1", 4))` can be passed to `controller.applyInlineCommandToFormattedTextSelection(selection, MarkdownEditorCommand.BOLD)`. The command edits each selected paragraph/heading as one undo step, preserves unselected blocks and link destinations, and validates the result against CommonMark before committing. Partial ranges inside existing bold, italic, and links are supported when a source-safe Markdown representation exists. Stale source snapshots, intervening non-text blocks, nested links, code/wikilink intersections, unsafe or Markdown-ambiguous link destinations, split UTF-16 surrogate pairs, and syntax that cannot retain the original visible text and marks are rejected without changing history. In Formatted mode, tap a paragraph, heading, or eligible list item at the desired caret position and use **Set start**; tap the other position and use **Set end**. The selected characters are highlighted, and **Copy Markdown**, **Delete text**, and **Replace text** operate on that source-bound range. Complete bullet lists, ordered lists, fenced or indented code blocks, and GFM tables between character endpoints are selected atomically: Copy preserves their exact source, while Delete and Replace remove them in one undo step. Character endpoints in a simple top-level list item’s first and only text line now support Copy Markdown, Delete text, and Replace text, including ranges through sibling items and complete intervening list/code/table blocks. The list marker and untouched source outside the range are preserved; a copied partial item includes its original marker. An edit is rejected if a surviving sibling marker would stop parsing as a list item. Nested items, continuation lines, items containing other block parts, code/table character endpoints, and inline marks across structured blocks remain unsupported. A long press followed by a drag into another paragraph or heading proposes a prose character range, with custom draggable endpoint markers. This replaces the old paragraph/heading whole-block long-press drag; tap the **Select** buttons on block headers to select complete blocks. Single-field text editing and list/table drag selection remain separate. These cross-field touch gestures still need physical-device validation; they do not use Compose's native cross-field selection handles. Unsupported intervening blocks and unsafe inline syntax are rejected without editing the document.

Pasting a multi-line nested list into a formatted list item keeps its marker, untouched siblings, inline source fragments, and one-step undo. The last pasted child item receives the formatted caret. A trailing fragment from the original item needs a separate parent paragraph, which makes that list loose under CommonMark; ambiguous trailing headings, quotes, and rules are rejected rather than reinterpreted. Plain nonblank lines stay editable in the formatted item. Pasted blank lines and other multiline input that the formatted list fields cannot safely represent are kept in the Markdown source in one undo step; the editor opens and focuses Source at the insertion point. The source may contain multiple paragraphs or other Markdown blocks within the item after such a paste.

Formatted mode also accepts `customBlockMatcher`, `customBlockBuilder`, and `customBlockEditorBuilder`. The matcher must explicitly identify blocks owned by the host; without it, every block keeps its default view. For example, match `block.kind == MarkdownBlockKind.RAW && block.source.startsWith("<my-card>")`, render a Compose card, and call the supplied `edit`, `replaceMarkdown`, `delete`, or `finishEditing` actions. Replacement and deletion return `false` if the document changed since the view was built or if reparsing would alter neighboring blocks. A successful action is one source-backed undo step, including when replacement changes the block syntax.

For a host-owned `:::custom` block, register `DelimitedBlockPlugin("custom")` and pass the registry to `MarkdownEditorController(markdown, parserPlugins = plugins)`. The editor then uses the same registry for its source-backed blocks and Reader preview. Match `block.kind == MarkdownBlockKind.RAW && block.source.startsWith(":::custom")` to show a host Compose view and editor. The block's exact Markdown, including line endings, remains available in the callback. Subclass `DelimitedBlockPlugin` to customize its Reader rendering. More complex syntax can implement `BlockParserPlugin` for Reader parsing and `SourceBlockParserPlugin` for whole-document editor spans; `SourceBlockParseResult.linesConsumed` must stay within the remaining input and cover complete top-level CommonMark blocks. Invalid or null results fall back to CommonMark.


`MarkdownStyleSheet` supports MaterialTheme-backed defaults plus `light()`, `dark()`, `github(dark)`, and `vscode(dark)` presets. Use `copy` to override colors, text styles, or spacing:

```kotlin
SmoothMarkdown(
    markdown = content,
    styleSheet = MarkdownStyleSheet.github(dark = true).copy(
        linkColor = Color.Cyan,
        blockSpacing = 16.dp,
    ),

```

The demo's Theme button cycles through all presets. This first native style API covers common reader elements; Flutter's full stylesheet includes additional properties such as alternating table rows and separate inline-format styles.

Code blocks accept `codeBlockDecoration = MarkdownCodeBlockDecoration(backgroundColor, borderColor, borderWidth, cornerRadius)` and `codeBlockPadding = PaddingValues(...)`. These match Flutter's actively rendered code block decoration and per-edge padding. Existing `codeBackground` and uniform `codePadding` remain supported; a decoration fill takes precedence over `codeBackground`.

Math uses the native [RaTeX Android renderer](https://github.com/erweixin/RaTeX) for formulas including fractions, roots, and scripts. Unsupported TeX shows its source text. In enhanced mode, `CodeBlockOptions` controls copying, language labels, and preliminary highlighting for Kotlin, Swift, Dart, Java, JavaScript/TypeScript, Python, JSON, Bash, and SQL. The public `codeBlockBuilder` and `onCodeCopied` parameters allow custom code rendering and copy handling.

## Parser and renderer plugins

Plugins are disabled by default. Create a registry before composing the reader and pass it to `SmoothMarkdown`:

```kotlin
val plugins = remember {
    ParserPluginRegistry().also {
        it.registerAll(listOf(MentionPlugin(), HashtagPlugin(), EmojiPlugin(), AdmonitionPlugin(), MermaidPlugin(), ThinkingPlugin(), ArtifactPlugin(), ToolCallPlugin()))
    }
}
SmoothMarkdown(markdown = content, plugins = plugins)
```

`InlineParserPlugin` provides a one-character trigger, `canParse`, `parse`, and `render` hooks. `BlockParserPlugin` provides `canStart`, `createNode`, `isClosingLine`, `complete`, and a Compose `RenderBlock` hook; the node-aware `isClosingLine(node, line)` variant supports multiple delimiter styles. Its `parseFencedCodeBlock` hook converts CommonMark fenced blocks while preserving ordinary code on a `null` result. Custom nodes extend `PluginInlineNode` or `PluginBlockNode`. A `null` parse result lets the next plugin or CommonMark handle the source. Higher priorities run first; equal priorities keep registration order. Registry IDs must be unique within the block or inline group. `copy`, `clear`, lookup, and unregister operations are available. Configure the registry before passing it to Compose; provide a new registry instance after changing its contents so the Markdown AST is rebuilt.

`MarkdownBuilderRegistry` overrides the rendering of parsed nodes, including built-in nodes. It is separate from `ParserPluginRegistry`, which controls syntax. Android registers CommonMark node classes instead of Flutter's string node types. An exact class match with `canBuild == true` wins; otherwise registered builders are tried in insertion order, then the built-in renderer handles the node. The registry is forwarded by both `StreamMarkdown` overloads and by `SmoothMarkdownEditor` in Preview and Split. Configure it before composing and supply a new instance when changing registrations.

```kotlin
val builders = remember {
    MarkdownBuilderRegistry().register(Heading::class, object : MarkdownNodeBuilder {
        override fun canBuild(node: Node) = node is Heading && node.level == 1
        @Composable override fun Render(node: Node, context: MarkdownBuilderContext) {
            context.renderInlineChildren(node, MaterialTheme.typography.headlineLarge)
        }
    })
}
SmoothMarkdown(markdown = content, builderRegistry = builders)
SmoothMarkdownEditor(controller = editorController, builderRegistry = builders)
```

`MarkdownBuilderContext.renderChild`, `renderChildren`, and `renderInlineChildren` reuse the same registry for nested nodes. For nodes inside a line of text, implement `renderInline` to return `MarkdownInlinePresentation.Text` or `Widget`; a widget needs explicit width, height, and copy fallback text because Compose lays out the paragraph before composing inline content. Returning `null` keeps the native inline rendering. A standalone image uses `Render` directly, while an image among text uses `renderInline`. The editor's Formatted mode keeps its separate `customBlockBuilder` and `customBlockEditorBuilder` hooks. Custom block rendering owns its selection semantics; the reader cannot infer selection geometry for an arbitrary Compose subtree.

The built-in plugins match Flutter's mention, hashtag, emoji, admonition, and Mermaid fence syntax. Emoji supports a custom shortcode map. Admonition content is parsed as Markdown. The opt-in Thinking, Artifact, and ToolCall plugins parse Flutter's corresponding AI chat block syntaxes. Thinking starts collapsed and can be expanded; artifact and tool inputs are rendered as selectable text without executing HTML or tool calls. Code artifacts reuse the native code block renderer. These readers do not yet provide artifact download, live tool status updates, or rich HTML/component previews.

## Mermaid prototype

`MermaidDiagramView(source)` is a standalone Compose view backed by `MermaidParser` and `MermaidLayout`. Register `MermaidPlugin()` to render supported fenced `mermaid` blocks in `SmoothMarkdown` or `StreamMarkdown`; without it, fences remain ordinary code. Empty or unsupported diagram families also remain code. Both backtick and tilde fences are recognized; the parsed node retains fence type, info, and optional `theme=` metadata. A fenced `theme=default|dark|forest|neutral` selects Flutter's matching Mermaid colors (unknown names use Flutter's light fallback); without `theme=`, the diagram keeps the host Compose colors. Standalone `MermaidDiagramView` accepts the same optional `theme` parameter. Supported flowchart syntax: `graph`/`flowchart` with `TD`/`TB`/`BT`/`LR`/`RL`; plain nodes and rectangle, rounded, stadium, diamond, hexagon, circle, subroutine, cylinder, asymmetric, parallelogram, and trapezoid node declarations; chained solid/thick/dotted edges with `|label|`; `classDef`, `class`, inline `style`, and nested `subgraph` membership. Supported sequence syntax: `sequenceDiagram`, `participant`/`actor` with aliases, and `->`, `-->`, `->>`, `-->>`, `-x`, `--x`, `-)`, `--)` messages with optional labels. Pie supports title, `showData`, quoted or unquoted labels, positive decimal slices, percentages, and a legend. Timeline supports title, period/event rows, multiple events per period, and descriptions. Gantt supports titles, sections, explicit dates, day/week/month/year durations, task status, dependencies, milestones, and a scrolling date grid. Kanban supports columns, task metadata, priority colors, WIP badges, and `ticketBaseUrl` frontmatter parsing. Radar supports labeled axes and curves, scale options, polygon/circle graticules, and a legend. XYChart supports category labels, numeric y range, grouped bars, line series, negative values, and horizontal orientation. ER diagrams support entity aliases, attribute compartments, labeled solid or dotted relations, and all four cardinalities at both endpoints. Flowcharts now preserve nested `subgraph` containers, group edges, and accessibility group labels; Flutter issue46 and group-boundary fixtures are covered by unit tests. The Canvas renderer draws these diagram types natively with scrolling for larger content.

For a quick local preview after installing the Demo APK, run `adb shell am start -n com.jackcaow.smoothmarkdown.demo/.MermaidDemoActivity` and use the button to cycle through flowchart, sequence, pie, timeline, Gantt, Kanban, Radar, XYChart, and ER. Gantt renders Flutter-style UTC day, Monday-week, and month header ticks based on the visible date span; `todayMarker` draws the current-day line when it falls within the chart range; `excludes` and `axisFormat` are parsed but do not change the chart, matching the current Flutter painter.  Kanban ticket URLs are retained but not opened. XYChart numeric x-axis ranges are retained but still use series indices for point positions. ER layout uses a simple non-overlapping row or column and does not yet provide full Dagre routing for dense graphs. Other Mermaid diagram families, advanced flowchart routing and shapes, non-state self loops, composite state blocks, sequence notes/activation/control blocks, responsive layout, and full Flutter visual parity remain open.
